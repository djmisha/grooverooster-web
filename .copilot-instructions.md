# Copilot Instructions

## Project Overview

Next.js 15.2.4 events application for location-based music event discovery.

### Technology Stack

- **Framework**: Next.js 15.2.4 (App Router)
- **Language**: JavaScript/TypeScript
- **Styling**: Tailwind CSS (no new SCSS files)
- **UI Components**: ShadCN UI, Radix UI
- **State**: React Context API
- **Database**: Supabase
- **Package Manager**: Yarn (v1.22.19)
- **Node**: 20.0.0

### Development Commands

- Install dependencies: `yarn install`
- Dev server: `yarn dev` (http://localhost:3000)
- Build: `yarn build`
- Lint: `yarn lint`
- Production: `yarn start`

## Core Development Principles

### Task Approach

- Read existing code patterns before making changes
- Make minimal, focused changes
- Run `yarn lint` and `tsc` frequently
- Check if components already exist before creating new ones
- Match existing component structure and styling approaches
- Test responsive design on multiple screen sizes

### Code Quality Standards

- Follow Airbnb JavaScript Style Guide strictly
- write self documenting production ready code
- Use ES6+ features consistently
- Prefer `const` over `let`, never use `var`
- Use arrow functions for components and methods
- Destructure props and state
- Use template literals for string interpolation
- Always use semicolons
- Use 2-space indentation
- Use single quotes for strings

### File Naming Conventions

- Components: PascalCase
- Utilities: camelCase
- Pages: kebab-case or nested folders (Next.js convention)

### Import Order

1. React and React-related imports
2. Next.js imports
3. Third-party libraries
4. Internal utilities and helpers
5. Components (general to specific)
6. Styles (if any)

## React Component Guidelines

### Component Structure

- Use functional components with hooks only
- Keep components small and focused (single responsibility)
- Place hooks at the top of components
- Define event handlers with `handle` prefix
- Place useEffect calls after handlers
- Always define PropTypes for all props
- Use defaultProps for optional props
- Use semantic HTML elements
- Add accessibility attributes (aria-label, alt text, etc.)
- Handle loading and error states explicitly

### State Management

- Use `useState` for local component state
- Use `useReducer` for complex state logic
- Lift state up when multiple components need access
- Use Context API sparingly for truly global state only
- Prefer derived state over storing redundant data

### Performance Optimization

- Use `React.memo()` for frequently re-rendering components
- Use `useMemo()` and `useCallback()` for expensive calculations
- Avoid creating objects/arrays in render methods
- Use lazy loading for heavy components
- Optimize images and assets

### Conditional Rendering

- Use short-circuit evaluation for simple conditions
- Use ternary operator for if/else scenarios
- Extract complex conditional logic into separate functions

## Styling Guidelines

### Tailwind CSS (Primary Approach)

- Use utility-first Tailwind classes for all new development
- Follow mobile-first responsive design (use `sm:`, `md:`, `lg:`, `xl:` prefixes)
- Organize Tailwind classes by category (layout, spacing, typography, colors, effects)
- Create reusable component patterns using Tailwind
- Use custom @layer components for repeated patterns
- Never create new SCSS files

### ShadCN UI Components

- Use ShadCN components as the primary choice for common UI patterns
- Extend ShadCN components with custom brand colors
- Check for existing ShadCN components before creating custom ones
- Maintain design system coherence across all components

## Database & API Patterns

### Supabase Integration

- Import from `@/features/Supabase` for client-side operations
- Import `supabaseAdmin` from `@/features/Supabase` for admin operations (API routes only)
- Use `supabase` client for user-scoped operations
- Use `supabaseAdmin` only in API routes for admin operations
- Never expose service role key in client-side code
- Always handle errors from database operations
- Use try/catch blocks for async database calls

### Required Environment Variables

- `SUPABASE_URL`: Supabase project URL
- `SUPABASE_ANON_KEY`: Public anonymous key for client
- `SUPABASE_SERVICE_ROLE_KEY`: Admin key (server-side only)

### API Routes Best Practices

- Keep API routes in `/app/api/` directory
- Always validate request method (GET, POST, etc.)
- Return appropriate HTTP status codes
- Use try/catch for error handling
- Never expose sensitive data or keys
- Validate and sanitize all inputs
- Follow RESTful conventions

## Next.js Specific Guidelines

### Pages and Routing

- Use app-based routing
- Implement proper SEO with meta tags
- Use server and client components appropriately
- Optimize for Core Web Vitals

### Performance

- Use Next.js Image component for optimized images
- Implement proper caching strategies
- Use static generation when possible
- Use dynamic imports for code splitting
- Tree-shake unused imports
- Monitor and optimize bundle size

## Error Handling

### Error Boundaries

- Implement error boundaries for critical components
- Provide meaningful error messages to users
- Log errors for debugging

### Async Operations

- Always use try/catch blocks
- Handle loading and error states in UI
- Provide user feedback for async actions

## Security Guidelines

- Validate all user inputs
- Sanitize data before rendering
- Use HTTPS for all external requests
- Avoid exposing sensitive information in client-side code
- Implement proper authentication and authorization

## Documentation & Comments

- Use JSDoc for function documentation
- Comment complex logic and business rules only
- Avoid obvious comments
- Keep comments up to date with code changes
- Document component props and usage examples

## Testing Guidelines

- Test component behavior, not implementation details
- Use React Testing Library
- Test user interactions and accessibility
- Mock external dependencies
- Test error states and edge cases

## Git Commit Guidelines

- Use conventional commit format
- Keep commits atomic and focused
- Write descriptive commit messages
- Use present tense

## Common Pitfalls to Avoid

- Don't create new SCSS files (use Tailwind instead)
- Don't add unnecessary dependencies
- Don't skip PropTypes validation
- Don't ignore accessibility attributes
- Don't break existing functionality
- Don't skip responsive design considerations
- Don't use `var`
